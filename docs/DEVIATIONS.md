# Deviations — honest deployment record

Each entry states the deviation, why it exists in this environment, and the
closest implemented alternative or the exact production integration point.
Safety invariants (determinism, human decisions, audit chain, fact-lock, no
source-system writes) are unchanged.

| # | Deviation | Reason | Implemented alternative / integration point |
| --- | --- | --- | --- |
| D-1 | One Next.js app (App Router, API routes, in-process background jobs) instead of a Turborepo with a separate Fastify API, workers and CLI service | The hosted environment runs one Next.js service | All logic lives in `src/lib/**` with no Next imports; API mirrors `/api/v1`, RFC 9457 errors, idempotency and If-Match. The CLI (`scripts/mizan.ts`) is independent of the server. Splitting into apps is mechanical. |
| D-2 | SQLite (Prisma) instead of PostgreSQL 16 with RLS and partitioning | No PostgreSQL server in this environment | The schema is tenant-scoped; single-tenant demo. `RUN_DATABASE_URL` can point Prisma at Postgres after a provider change; RLS policies and month partitions remain a production task. Cross-tenant 404 semantics are **not** proven against a real second tenant. |
| D-3 | In-process TTL cache with single-flight instead of Valkey | No Valkey | `src/lib/server/cache.ts` is non-authoritative, bounded and disable-able (`CACHE_DISABLED=true`). Analytics still work with the cache off. |
| D-4 | Local content-addressed object store instead of S3/MinIO with object lock | No object-store service | `src/lib/server/object-store.ts` writes immutable SHA-256-keyed files and is used for uploaded raw files and evidence packs. Production swaps in an S3-compatible bucket with WORM; the manifest and verification code are unchanged. |
| D-5 | Judge role switcher + `X-Mizan-Actor` header instead of OIDC (Entra ID/ADFS) | No identity provider | The API enforces the role matrix, conflict-of-interest guard and two-person rules regardless of identity source. **The header is not a real authentication boundary**; production must replace `resolveActor` with OIDC session validation and CSRF tokens (the spec's EC-N08 remains a production task). |
| D-6 | Runs execute synchronously inside the request (the request waits for finalize) instead of a pg-boss worker fleet with shards and leases | Single-process environment; un-awaited work is cancelled when a Next route returns | Evaluation is pure and deterministic, so a retry is safe. Run status, manifest, per-run snapshots, outbox, inbox and the notification DLQ are real. The queue/shard/lease/fencing layer remains a production task. |
| D-7 | Judge Reset truncates history (audit, runs, exceptions) for a <5 s restore | Demo needs a fast clean slate | Documented judge-only route; production exposes no reset endpoint. |
| D-8 | The NE spike guard applies the 5% rate test only at ≥50 applicable checks, plus a 3× baseline count test | A two-transaction denominator would fire permanently on the demo pack | ADR-0006; the count test still applies to small samples. |
| D-9 | k6 load, two-site active-active, split-brain drills and weekly restore proofs are configuration/runbooks, not executed here | No second site, no chaos infrastructure | `infra/k6`, Helm values and RB-03/04/05 document the procedures; the audit chain and module-boundary tests that they depend on are implemented. |
| D-10 | Determinism self-check re-evaluates the full pack instead of a 1% sample | 15,915 checks evaluate in under 1 s; a full pass is stronger | Same FS-03 gate semantics. |
| D-11 | The duplicate Critical modifier (both effective in a closed payroll period) is skipped because no payroll calendar is provided | Inventing a closed period would be a guess | Rationale stored on every duplicate; adding `config/payroll-calendar` activates it (ADR-0004). |
| D-12 | The model gateway is implemented but narrative jobs are not scheduled automatically; templates are always the shipped explanation | `ai.mode` defaults to `none`; no model endpoint is configured in this environment | `polishNarrative` has real `local` and `provider` adapters, redaction, deadlines and fact-lock. Provider mode requires `MIZAN_MODEL_PROVIDER_URL`; a configured deployment can add the `explain.narrative` job without touching the engine. |
| D-13 | Uploading `policy_rules.md` validates/hashes the file but does not compile arbitrary Markdown into new RuleSpecs; the shipped pack and the rule studio are the compilation path | A full policy compiler is a larger feature than this build; the shipped pack is the source of record | The rule studio (controlled grammar + guided builder) compiles new rules, and portable YAML packs import as drafts. A production policy compiler would extend `src/lib/pack/rules.ts`. |
| D-14 | Uploading `finding_format.csv` stores metadata/hash; the export profile is the compiled shipped profile | The five worked examples are the contract and are validated exactly | `src/lib/pack/finding-format.ts` is the profile; an importer can be added without changing the exporter. |
| D-15 | Only the demo tenant exists; no second tenant is provisioned to prove row-level isolation | Single-tenant judge profile | Every sensitive table carries `tenant_id`; keys are tenant-scoped. Do not claim RLS for production until D-2/D-5 are resolved. |
| D-16 | English/Arabic UI coverage is complete for overview, runs, queue, drawer and the rule studio's main flows, but Audit, Settings, Patterns and some table labels remain English-only | Time and surface area; the explanations, actions, rule citations and exports are fully bilingual | RTL mirroring works across the shell. A production pass should move the remaining hardcoded copy into the message catalogue. |
| D-17 | Accessibility was checked by keyboard/ARIA review and automated screen structure, not by a recorded NVDA/VoiceOver session or a full axe run | No assistive-technology session in this environment | Landmarks, skip link, labels, dual-coded severity and focus styles are implemented; run axe + AT before submission. |
| D-18 | Scale was verified at 1,061 and 10,000 transactions; the 1,000,000 × 20 / 16-shard target and two-machine determinism were not measured | Hardware/time limits | `mizan bench perf --scale 10k,100k,1m` exists and is seeded; run it on the submission hardware. |
| D-19 | `docker compose up` and Helm installation were not executed in this environment | No Docker daemon/air-gapped images | `infra/docker-compose.yml`, Dockerfile and Helm values are provided; the application itself starts with `bun run seed && bun run dev`. Do not claim the 10-minute compose red line until it is run. |
| D-20 | Live HR system connectors were removed rather than stubbed | The challenge explicitly excludes connecting to live systems and any write path | No adapter, credential or write path exists. If a pilot requires files, the upload API is the boundary. |
