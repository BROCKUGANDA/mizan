# Integrations — intentionally absent

MIZAN does **not** connect to Emirates' live HR or finance systems, and it has no
write path to any source system. That is a scope requirement of the challenge,
not a stub: there is no adapter, credential or disabled code path that could
perform a write.

## What replaces a connector

- **Input:** the upload API (`POST /api/v1/datasets`) accepts CSV/employees,
  policy Markdown and the finding format. It enforces 50 MB / 1 MB per line /
  2M rows, sniffs the encoding and delimiter, hashes the bytes, scans for PII,
  deduplicates by content and records a schema fingerprint for drift.
- **Output:** findings CSV, data-quality CSV and evidence packs. All are
  generated by the engine; no external system is called.
- **Notifications:** the transactional outbox delivers in-app messages. Email
  and webhook delivery are disabled unless both a flag and an endpoint are
  configured (`MIZAN_SMTP_URL`, `MIZAN_WEBHOOK_URL`); failures dead-letter and
  can be replayed with `mizan dlq replay`.
- **Identity:** judge-mode role switching. Production must replace
  `resolveActor` with OIDC; the role matrix, CoI guard and two-person rules are
  already enforced in the API.

## Non-negotiables

1. No write credentials exist in the repository.
2. Every input is synthetic or explicitly confirmed test data; the PII scanner
   blocks Emirates ID, passport, IBAN, phone and email patterns.
3. The engine is pure: it never reads free text for a decision, and no model can
   change state.
4. Corrections are recommendations a human applies in the system of record.
