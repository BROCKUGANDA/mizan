# RB-03 — Integrity failure (safe halt)

Steps: detect → contain → recover → verify → communicate.

- Detect: `integrity.verify` fails (hourly job or on-demand) → the system enters M5; new runs and decisions return MZ-RUN-423 / MZ-MODE-503.
- Contain: automatic. Freeze administrator role changes and snapshot the database.
- Recover: find the first failing chain segment (`GET /api/v1/audit/verify` → firstBadSeq) and compare with the immutable object-store copy of the chain. If tampered, restore from the immutable copy and open a security incident. The tamper demonstration (Audit room, admin only) shows the detection path live.
- Verify: full chain verification passes and one verification run reproduces the last run's output hash.
- Communicate: compliance lead and audit within 1 hour; record the incident. Clearing M5 needs an administrator reason, verification pass, and a second administrator countersign, passing through M4 for one verification run.
